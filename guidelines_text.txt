1. Project Overview 
The Final AI Capstone Project requires students to design and develop a working AI-based application that 
addresses a practical problem. The project should demonstrate how AI concepts can be applied to solve a real-
world problem and should be appropriately scoped for the course development period. 
Students may use pre-trained AI/ML models, LLM APIs, LangChain, RAG, public datasets, and existing Python 
libraries/frameworks. Students are NOT required to train an AI model from scratch. 
2. Project Requirements 
• A. Clearly Defined Problem: Identify the problem, target users, and why the problem is relevant or useful. 
• B. One AI Component: Use an appropriate AI technique such as LLM, RAG recommendation along with 
Classification / regression, etc. 
• C. Working Prototype: Develop a functioning application that allows a user to interact with the system and 
observe meaningful output.

4. Research Component 
Each project must be supported by at least ONE relevant research paper or credible technical article. The 
purpose is to connect the student project with an existing AI application or research approach. 
Students should identify: 
• The problem addressed by the paper/article 
• The AI technique or model used 
• The dataset or knowledge source 
• The system approach or architecture 
• The evaluation method 
• How the student's project is different from or simpler than the referenced work 
Important: Students are NOT expected to reproduce the research paper. They should use the research as 
inspiration and implement a simplified version appropriate for a Bachelor-level project. 
5. Suggested System Structure 
A typical project may follow this structure: 
Problem → Data / Knowledge Source → Pre-processing → AI Technique → Model / LLM → Output → User 
Interface → Evaluation 
For an LLM + RAG project: 
Documents → Chunking → Embeddings → Vector Store → Retrieval → Prompt → LLM → Answer 
6. Project Proposal 
Before development, students should submit a 1-page project proposal containing: 
1. Project Title 
2. Problem Statement (2–4 sentences) 
3. Target Users 
4. Proposed AI Solution 
5. AI Technique / Model 
6. Dataset or Knowledge Source 
7. Proposed System Architecture (simple diagram) 
8. At least ONE relevant research paper/article 
7. Final Deliverables 
1. Project Report 
5–8 pages. Suggested sections: Introduction; Problem Definition; Related Work; Methodology; System 
Architecture; Implementation; Results/Evaluation; Limitations; Conclusion; References. 
2. Working Prototype 
Source code, notebook/Python files, dataset or data-source information, and instructions required to run the 
system.

3. Presentation 
Approximately 7–10 minutes per student. Cover the problem, solution, research inspiration, architecture, demo, 
results, limitations, and future improvements. 
4. Demonstration 
Demonstrate the actual working system. Screenshots alone are not considered a successful demonstration.

9. Detailed Rubric Descriptors 
Problem Definition & Relevance — 10 marks 
• 9–10: Clearly defined, meaningful problem with well-identified target users and strong justification. 
• 7–8: Clear and relevant problem, but justification or target users could be stronger. 
• 5–6: Basic problem identified but lacks depth or clarity. 
• 0–4: Problem is unclear, unrealistic, or poorly justified. 
Research & Background — 10 marks 
• 9–10: Uses relevant research/technical sources, clearly explains related approaches, and connects them 
to the project. 
• 7–8: Relevant sources with reasonable understanding. 
• 5–6: Limited research with basic connection to the project. 
• 0–4: Little/no relevant research or sources are poorly used. 
AI Methodology & Technical Understanding — 20 marks 
• 18–20: Correctly explains the selected AI technique, architecture, components, and why they are 
appropriate. 
• 14–17: Good understanding with minor technical weaknesses. 
• 10–13: Basic understanding with significant gaps. 
• 0–9: Cannot adequately explain how the AI component works or why it was selected. 
Implementation & Working Prototype — 25 marks 
• 22–25: Fully functional prototype; AI component works reliably and is well integrated. 
• 18–21: Mostly functional with minor issues. 
• 13–17: Partially functional with some major limitations.

• 0–12: Prototype is largely incomplete or non-functional. 
Data / Knowledge Processing — 10 marks 
• 9–10: Data/knowledge source is appropriate, well prepared, and processed correctly. 
• 7–8: Appropriate data with reasonable preprocessing. 
• 5–6: Basic processing with some issues. 
• 0–4: Poor-quality, inappropriate, or unexplained data. 
Evaluation & Results — 10 marks 
• 9–10: Appropriate evaluation/testing with clear results and meaningful analysis.

• 5: Well-structured report, clear writing, appropriate citations and references. 
• 4: Generally well-written with minor issues. 
• 2–3: Basic report with organization/reference problems. 
• 0–1: Incomplete, poorly structured, or insufficient references. 
10. Project Rules 
Students may use: LLM APIs; open-source/pre-trained models; LangChain; RAG; public/Kaggle datasets; Python 
libraries; Streamlit; GitHub; and AI-assisted coding tools. 
Students may NOT: submit another person's complete project; copy a Kaggle notebook and present it as their 
own; reproduce a research implementation without meaningful adaptation; submit a project they cannot explain; 
or include API keys/passwords in their submission. 
AI-assisted coding: Students may use AI coding assistants, but they are responsible for understanding, testing, 
debugging, and explaining all submitted code.

11. Tool Selection 
Students should select tools that are appropriate for their chosen problem. LangChain is recommended for 
LLM/RAG projects but is not mandatory when it provides no meaningful benefit. For example, a traditional spam 
classifier may appropriately use Python and scikit-learn without LangChain. 
12. Scope Limitation 
A simple project that works well is better than a complex project that is incomplete. 
The project should be appropriately scoped for a short development period. Students should prioritize a working 
and evaluated prototype rather than attempting to build a large or highly complex system.
