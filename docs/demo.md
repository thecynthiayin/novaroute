# Capstone demonstration (8–10 minutes)

1. Start MySQL, Mailpit, FastAPI and Next.js; run migrations and `--demo` seeding. Open Mailpit in a second browser tab and the employer account in an incognito window. Use the explicit demo indicator to explain which parts are deterministic and which use real MiniLM inference.
2. Show the landing page and switch light/dark/system. Sign in as `student@novaroute.test` with `NovaRouteDemo!2026`. Point to real dashboard totals and the strict similarity explanation.
3. Open My profile. Add coursework and a project, then save and reload to demonstrate persistence. Upload `frontend/tests/fixtures/resume.pdf`, review the skill draft, correct any details, and confirm. Explain that employers never receive the private PDF. Use a fresh profile or unchanged version when confirming.
4. Show recommendations. The supplied realistic profiles may have **no score above 0.80**; that honest empty state is expected, not a broken model. Browse all internships, filter by skill/work mode, inspect a listing, save it, and edit its private note.
5. Apply with a cover message. Show the application-time snapshot and editable cover message before review. In the employer window (`employer@novaroute.test`, same password), open the applicant and set Viewed with a useful note.
6. Refresh the student's inbox or wait for its 25-second poll. Show the persisted status, demo advice, timeline, and Mailpit's HTML/plain-text email. Disabling email preferences leaves in-app history intact.
7. Post a new employer listing. Show pending then active content review. Edit the description to include an explicit “upfront fee”; save and show the flagged state and correction suggestion. Remove the problem and request fresh review. Close/reopen/delete to demonstrate ownership-controlled CRUD and preserved applications.
8. Withdraw a nonterminal student application with confirmation. Explain terminal decisions and why duplicate/repeat applications are rejected. Open account settings to show email preferences, password change and deactivation confirmation without deactivating a shared demo account accidentally.
9. Show `docs/evaluation/results.json`: real CPU MiniLM versus keyword overlap on the same tiny synthetic set, with proposed labels and clear limitations. This is pretrained inference/API integration, not a newly trained model and not a hiring-probability system.

For a controlled positive high-match demonstration, run the opt-in real-model test in the isolated `novaroute_test` database. It constructs a clearly synthetic profile whose project directly matches the listing, measures the actual cosine (>0.80), and verifies one persistent alert despite repeat evaluation. The measured test value during implementation was approximately **0.958999**. This positive-control test is separate from the realistic three-profile evaluation and must not be presented as broad model accuracy.

Failure demonstrations: use a plain text file with `.pdf` extension (rejected), an image-only PDF (searchable text required), an incorrect password (generic login failure), a stale profile version (409), and an unavailable live OpenRouter configuration (manual entry remains usable; listing remains pending). Do not enter real student private data or send real email during a demonstration.
